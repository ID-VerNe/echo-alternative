# RFC 0001：把一本书编译成 LLM 说话工作流（Book → Style Pipeline）

> 状态：草稿（记录想法，未进入实现）
> 语料：克拉克森（Jeremy Clarkson）中文版 23 个书目 / 671 个 PDF 分卷

## 一句话

输入一本书（或同一作者的一批书），输出一套可复用的**风格资产包 + 固定生成管线**，让模型在新话题上用作者的方式说话。

## 要解决的问题

三种常见做法都到不了目标：

| 做法 | 问题 |
|---|---|
| 纯人设 Prompt | 只能产出形容词缝合怪（"幽默风趣""犀利毒舌"），换个话题立刻变回标准 AI 腔 |
| 普通 RAG | 按知识点检索，只能复述书里有的东西，无法生成作者会怎么谈一件书里没有的事 |
| SFT / LoRA | 语感最自然，但数据清洗难、每换一本书要重训、容易过拟合原话题或掉智商 |

本方案选 **Workflow + 风格资产包**：全自动、冷启动成本低、换书即换人。微调不是替代品，而是后续可选加固（见 D7）。

## 总体架构

双阶段解耦：离线把书加工成机器可读的风格资产，在线用固定管线做内容与风格分离（Content-Style Decoupling）的生成。

```
阶段 A（离线）  书 → 清洗 → 双层切片 → 双轨特征提取 → 锚点库
                                        ↓
                        style_spec.json  +  style_anchors.db

阶段 B（在线）  用户输入
                   ↓
              [1] 意图/语境分类 ──► 检索 3~5 段同语境原声锚点
                   ↓
              [2] 草稿：事实清单（不成句）
                   ↓
              [3] 风格转译：注入 spec + 锚点，重新成句
                   ↓
              [4] 质检：规则优先，命中才局部重写
```

## 阶段 A：离线提取管线

### A1 语料清洗

剔除目录、版权页、他人引语、纯客观资料罗列，只保留作者本人的"发声段落"。
克拉克森这批书的额外处理：车评里大量参数罗列（马力/扭矩/售价）属于非风格段落，需要按段落类型过滤，但保留"拿参数当梗用"的句子。

### A2 双层切片

| 粒度 | 长度 | 用途 |
|---|---|---|
| 段级 | 200–500 字 | 代码统计、特征归纳 |
| 句级锚点 | 3–8 句 | Few-shot 注入 |

理由：风格信号集中在**句首 1–2 句的起手式**和**句尾的收束方式**（尤其"不升华"这种反直觉动作）。整段注入时模型看到的是内容，不是节奏。

段级切片按语义完整度切分，并打语境标签：`议论/说理`、`叙事/举例`、`吐槽/反驳`、`自嘲/抒情`。

### A3 双轨特征提取

**代码硬统计（不让 LLM 猜）**

- 平均句长、句长分布（直方图）、长短句交替比例
- 标点偏好：破折号、括号、问号、省略号、感叹号频率
- 分句/换行习惯、段落句数
- 高频虚词与连接词、TTR、hapax 比例、成语/四字格密度
- 依存距离均值（嵌套深度）

**LLM 隐性特征（Map-Reduce 分批归纳）**

- 思维起手式：先抛反直觉结论，还是先讲小故事
- 类比偏好：生活琐事 vs 专业术语
- 情绪温度、攻击性、自嘲频率
- **反面约束（Negative Constraints）**：作者绝不会用的句式和词汇

### A4 锚点库（Style-RAG）

**不按知识点建索引，按"表达功能/语境"建索引。** 每条锚点：`{intent, text, source_book, style_intensity, pair_with_ai_version}`。

锚点必须**成对**：一条原声 + 一条"标准 AI 会怎么写"的对照版，指令是"学会从后者到前者的变换"，而不是"模仿前者"。这样能防内容串台，也让模型学到改写动作而非抄原句。

### A5 产出物

- `style_spec.json`：硬规则、思维骨架、禁词表（按 intent 分片，见 D2）
- `style_anchors.db`：带语境标签的原声语料 + 向量索引

## 阶段 B：在线推理

| 节点 | 做什么 | 关键约束 |
|---|---|---|
| 1 意图分类 | 判断当前该用哪种语境 | **用 embedding KNN，不调 LLM**（锚点自带标签，零延迟） |
| 2 草稿 | 把事实、逻辑、立场写准 | **输出结构化 notes，不成句**（见 D1） |
| 3 风格转译 | 静态注入 spec + 动态注入锚点，从零成句 | 锚点指令必须写明"只学断句节奏遣词，严禁带入示例中的具体事件和名词" |
| 4 质检 | 扫禁词、句长分布、n-gram 重叠 | 规则先跑，命中才升小模型重写 |

## 关键设计决策

**D1 草稿去句化（最重要）**
节点 2 输出的是立场、支撑事实、关键数字、要反驳的点、要举的例子、情绪落点——不是成句文本。草稿一旦成句，节点 3 的改写熵极低，模型会退化成"润色"，风格只能贴在最外层，逻辑一复杂就掉回 AI 腔。这个改动几乎决定成败。

**D2 spec 按语境分片**
同一作者在不同语境下（严肃论述 / 吐槽 / 闲聊）句法和节奏完全不同。单一全局 spec 会把风格平均化。`style_spec.json` 结构为 `{intent: spec}`，每个子 profile 可以很薄：5–8 条硬规则 + 2–3 条禁词。

**D3 锚点句级 + 成对**
见 A2/A4。配对样本比单纯原声片段更能防串台。

**D4 反面约束优先**
"要幽默风趣"几乎无效；"禁止排比句、禁止首先/其次/最后分点、每段不超过三句、禁止结尾升华总结"立刻立起来。禁词表是最高性价比的资产。

**D5 长规则要编译，不只靠缓存**
Style 节点把编译后的短 spec（≤800 token）放 System Prompt 顶部，动态锚点和草稿放 User Prompt 末尾，最大化 prefix cache。但更长远的做法是**离线把 30 条规则压成 12 条可执行指令**——规则越长，遵守率越低，这不只是成本问题。

**D6 候选重排比"检测→重写"便宜**
短回复直接生成 3 个候选，用规则+小模型打风格分选最好的，比 critic 全量重写少一次长上下文调用。critic 只在规则命中时触发。

**D7 Workflow 起步，微调收尾**
管线跑出来的、通过质检的对话天然是 DPO 偏好数据（chosen = 高风格分，rejected = 被 critic 打回的版本）。日志按这个格式存，以后想加轻量 adapter 时数据是现成的。

## 评估体系

目标：把"像不像"拆成可测的多维度量，先验证指标本身，再用指标调管线。

| 层 | 指标 | 抓什么 | 成本 |
|---|---|---|---|
| E1 作者距离 | 字符 3–5 gram Cosine Delta | 整体文风距离（内容无关） | 半天，纯 CPU |
| E2 判别器 | style classifier accuracy（1-vs-rest） | "像不像"的监督主指标 | 半天（embedding + LR） |
| E3 韵律 | 句长 JS 散度、标点 cosine、依存距离 | AI 腔 / 节奏塌陷 | 半天 |
| E4 裁判 | pairwise 盲测 + Bradley-Terry Elo | 版本对比排行榜 | 1 天 |
| E5 约束 | BERTScore/embedding cos、数字与专名保留率、5-gram 重叠率 | 内容被改错 / 抄原文 | 1 小时 |

要点：

- **Cosine Delta**：取 100–300 个高频虚词，z-score 后算夹角距离，可与作者语料的 centroid 比较。中文优先用字符 n-gram，免分词；单条回复短于 100 字时用 3–5 轮累积窗口。
- **判别器负样本**：同一批问题用通用模型生成一份 + 其他作者语料，构成 1-vs-rest。注意短文本上小模型会"自信地判错"，要与 Delta 交叉验证。
- **韵律层是抓 AI 腔最灵敏的一组**：AI 文本句长高度集中（20–30 字一刀切），真人分布长尾。
- **perplexity / fluency 不能当风格指标**：它天然偏袒通用平实文本，方向是反的。
- **meta-evaluation**：先人工标 100 条（像 / 勉强 / 不像），算各自动指标与人工标注的 spearman 相关，只有相关性够高才可信。跳过这一步就是优化一个不知道对不对的数字。

合成分建议做 0–100 的 Style Fidelity Score，但必须分维度展示——合成分会掩盖失败模式。

## 风险与坑

| # | 风险 | 应对 |
|---|---|---|
| R1 | 书面语 ≠ 说话方式 | "口语化降维"参数；锚点先做一次"口头讲述同一件事"的中间改写 |
| R2 | 锚点内容串台 | 锚点成对 + 指令明写"严禁带入示例事件名词" |
| R3 | **译作的语言是译者的** | 见 O1，这是本项目的头号结构性问题 |
| R4 | 长 spec 稀释注意力 | D5 编译压缩 |
| R5 | 判别器学到内容而非风格 | 负样本必须同主题（StyleDistance 的方法论正是为此） |
| R6 | 短文本 Delta 不稳 | rolling window |
| R7 | 版权与合规 | 语料只本地使用、不入库；对外产品需 AI 生成披露；模仿特定真人有署名/人格权风险 |
| R8 | 风格学过头变背原文 | 5-gram 重叠率长线监控 |

## 开放问题

**O1 中文译本的归属问题（必须先定）**
这批克拉克森全部是中文译本。抽出来的"风格"实际上是**译者中文 + 克拉克森内容结构**的混合物，不是克拉克森本人的英语语感。三条路：
- a) 承认目标是"中文克拉克森腔"，把译者的文风当作资产（最省事，但要接受它其实是译者风格）
- b) 找英文原版做风格提取，中文只做内容层（成本高，需另一套语料）
- c) 混合：英文提取思维骨架，中文提取语言节奏，做双源 spec

**O2 单书还是多书**
同一作者跨书风格差异很大（农场书是口语叙事，车评是讽刺短打，时评是政治吐槽）。是先做"克拉克森总集 profile"，还是先按书目聚类再做子 profile。建议先做单书（农场 1）跑通，再合并。

**O3 目标载体**
是聊天助手（多轮、短回复、要被追问）还是内容生成（长文、专栏体）？两者对句长分布和收束方式的要求相反。

**O4 评估金标准的标注成本**
100 条三档人工标注由谁做，是否需要第二标注者算一致性。

## 里程碑

- **M0 语料入库**：23 个书目 671 个 PDF → markdown，抽样校验转换质量（错字、断行、页眉页脚、图表丢失）
- **M1 最小闭环**：单书（建议《克拉克森的农场1》）+ 100 条测试问题 + E1/E3/E5 四维分数，2–3 天出第一组数字
- **M2 判别器与版本对比**：E2 + E4，spec v1 vs v2 可打分
- **M3 离线管线自动化**：换一本书全自动产出资产包
- **M4（可选）**：用积累的偏好数据做轻量适配器加固
